## 1. 敌人：保留原画，改善空间表现

- **没有替换或重绘** `assets/蓝色大肥鱼.png` 和 `assets/fish-texture.js`。脸、头发、衣服、整体轮廓继续来自原素材。
- 普通敌人与 Boss 的单面板改为 **12×12 分段的浅弧面**，增加一个紧贴原画的深色背层，形成很薄的立体边缘。这属于 2.5D 浅浮雕，并非完整的角色三维建模。
- 增加轻微呼吸伸缩、较小幅度的左右摆动和接地软阴影；跳起时软阴影扩大、变淡。分裂子鱼显示为原体型的 72%。
- 广告牌只跟随水平视角，玩家抬头、低头时，角色不会整张向地面翻倒。Boss 同样处理。
- 修正原有抠图：旧逻辑会全图删除接近白色的像素，导致白衣、眼白、头饰出现透明洞。现在只删除与图片边缘连通的背景区域，原图内部的白色被保留。
- 将 `customDepthMaterial` 正确挂在 Mesh 上，投影使用角色透明轮廓。角色原画保持不受色调映射影响，以保证辨识度。

新增 `js/combat-art.js`，通过程序化低面数模型和轻量特效改善战斗表现，无需外部模型下载。

| 部分 | 本次改动 |
| --- | --- |
| 玩家手枪 | 倒角套筒、圆形枪管、枪口内孔、防滑刻槽、发光照门、握把和简化手套；套筒随射击后坐 |
| 玩家步枪 | 重做机匣、护木、散热槽、导轨、开放瞄具、枪托和弹匣；加入倾枪换弹与弹匣移动 |
| 匕首 / 小怪剑 | 刀刃改为有中脊和两侧斜面的真实几何，增加护手和握柄细节；匕首斜举便于辨认，轻重击继续使用原有时长和伤害 |
| 手雷 | 分段弹体、金属箍、保险环与压杆；飞行中增加翻转，落地爆炸规则沿用原实现 |
| Boss 武器 | 重做火箭筒、三管重炮、巨剑、召唤法杖；巨剑待机斜举、冲锋前指，法杖举起水晶与金属环 |
| 枪焰和弹道 | 枪焰使用交叉面与柔边纹理，位置来自真实枪口锚点；玩家示踪线连接枪口与本次射线的命中点，保留原准星命中逻辑 |
| 命中和爆炸 | 方块粒子改为圆形柔边、独立大小和透明度衰减；增加命中闪光、火光、上升烟尘、地面扩散环，自爆保留分层烟柱与蘑菇云冠 |
| 刀光和炮弹 | 玩家挥刀增加短暂弧光；Boss 炮弹改为带弹头、尾翼和尾焰的模型，跟踪转弯时模型头部同步朝向速度 |
| Boss 登场 | 缩小光环覆盖范围、降低光柱不透明度，避免在白天遮住大面积建筑；延迟出现的光环不再提前显示 |

**Boss 朝向修复的原因与约定：** 原模型混用了 `+Z` / `-Z` 枪口方向，重炮还被固定旋转 90°，同时武器继承了角色广告牌跟随相机的旋转。现在敌方武器统一 `+Z` 朝前，玩家武器保持 `-Z` 朝前。瞄准在世界坐标计算，再通过父节点的完整逆矩阵换算为局部姿态，兼容广告牌摆动和普通鱼呼吸时的非等比缩放。

- Boss 发射前更新瞄准与世界矩阵，弹丸直接取 `muzzleTip` 的世界位置及世界前向。
- 三管炮拥有三个独立炮管和枪口，左右炮管向外展开，三发炮弹分别从对应炮口出膛；原扇形散射角和速度配置保持不变。
- 射手鱼也按真实目标瞄准，取消子弹生成时人为向前跳过 0.7 米的偏移。
- 共享几何与材质继续使用 `artShared` 约定；新增烟团、示踪线、冲击环、刀光共用最多 **112 个对象**的复用池，普通粒子使用 **360 个槽位**。池满时替换最旧的视觉效果，不改变伤害计算。
- 暂停冻结玩家武器动作、枪焰、新特效、普通粒子与 Boss 登场演出；切枪恢复被打断的换弹姿势。原有敌人待机摆动仍沿用游戏视觉时钟。
- 关闭“粒子特效”时清理新特效和旧粒子；重开清空池中活动对象及粒子透明度。枪口短闪、原有必要攻击提示不受该开关影响。
- 炮弹销毁与重开时使用统一资源释放函数：共享缓存保留供下一局复用，独有几何正确释放。

## 4. 代码与性能维护

- 新增 `js/art.js`，集中管理材质、程序化纹理、场景细节、角色浅弧面和资源释放。删去 `game.js` 中已不再使用的旧美术生成函数。
- 固定数量的通用纹理、材质与基础几何体缓存复用；建筑装饰、草叶和台地采用 `InstancedMesh` 批量绘制。
- 场景纹理和装饰使用独立的固定种子随机数，绘制地图细节不会额外消耗战斗逻辑的 `Math.random()` 序列。
- 新波次开始时移除旧波次的死亡敌人，停止对应语音，并回收模型和阴影的临时资源。原实现会持续保留死亡对象。
- 回主菜单时递归回收环境几何、临时材质、贴图、实例缓冲和灯光阴影资源；修复随机掩体重开后未被完整卸载的问题。
- 补给拾取、手雷爆炸和重开清场时，释放相应临时模型资源。
- HUD 数值未变化时跳过重复 DOM 写入；小地图绘制限制为 30 次/秒，移动、射击与 3D 渲染仍按原帧循环运行。
- 修复暂停、技能或奖励界面中换弹计时仍推进的问题。恢复游戏后继续原有换弹进度。
- 随机掩体重新生成时重建小地图，避免地图显示上一局的箱子。
- 调试接口 `FishGame.__debug.getSceneStats()` 增加被跟踪敌人数、绘制调用数、三角形数、几何和贴图计数，便于以后排查。

资源释放约定：`userData.artShared` 标记长期共享的美术缓存；释放敌人时显式保护 `fishTex`。新增共享资源时请沿用这个约定，避免提前释放其他对象仍在使用的贴图或材质。

## 6. 启动、测试与回退

直接双击 `index.html`，或双击 `启动游戏.bat`，也可在此目录执行：

```powershell
node server.js
# 浏览器打开 http://127.0.0.1:8123/
```

浏览器测试需开发环境提供 Playwright。Windows 默认调用本机 Edge；其他系统需准备 Playwright Chromium。先启动服务器，再运行：

```powershell
node tests/browser-art-test.cjs
node tests/browser-combat-test.cjs
node tests/browser-wall-top-test.cjs
node tests/browser-scene-detail-test.cjs
# 已有外部 Playwright 时，可将 PLAYWRIGHT_MODULE 环境变量设为其模块目录。
# 可选 FISH_TEST_URL 指定服务器地址，FISH_TEST_OUTPUT 指定输出目录。
# 战斗截图输出目录可用 FISH_COMBAT_OUTPUT 指定。
```

**游戏运行本身无需安装新依赖，也没有新增 CDN、远程贴图或付费资源。** 当前脚本顺序为 `three.min.js → fish-texture.js → enemy-textures.js → art.js → scene-detail.js → combat-art.js → game.js`。

第一轮原始备份位于 `backups/codex-2026-10-21/`。第二轮开始前另存于 **`backups/codex-combat-2026-10-21/`**，包含 `index.html`、`js/game.js`、`README.md`、本说明文件及已有测试文件，未覆盖第一轮备份。

仅撤销战斗优化时使用第二份备份；撤销两轮修改时使用第一份。先关闭游戏，再按相对路径覆盖对应文件。新增模块与测试可保留，旧入口不会引用它们。备份不包含浏览器个人存档，存档结构两轮均未改动。`tests/e2e-test.js` 会启动自己的服务器，运行前应关闭占用 8123 端口的开发服务器。

## 7. 给后续开发者的建议

1. **先拆职责，再加玩法。** `game.js` 仍然较大。按“状态与时间、敌人 AI、武器、波次与成长、UI、音频”逐块抽离，保留现有行为测试。先继续用 classic script 也可以；是否迁移 ESM/Vite，应同时考虑双击离线启动的要求。
2. **统一碰撞与可见模型。** 当前主要依赖矩形障碍、障碍物网格射线与角色的逻辑球形命中体，棕榈等物体仍沿用原有近似碰撞。建议给地图对象提供统一的 collider/occluder 配置，并决定敌人采用稳定的逻辑命中体还是按原画 alpha 判定，避免以后美术变形无意改变射击手感。
3. **补敌人绕路能力。** 当前主要是直接追击和局部避障。沙漠走廊更适合简化网格 A* 或导航点图；索敌视线检查和寻路分帧执行，减少大量敌人同时更新的开销。
4. **为长局建立压力场景。** 自动刷入各类敌人、Boss、投射物和反复爆炸，记录数分钟的帧耗时与 `renderer.info.memory`。第二轮已验证战斗缓存和池容量；后续应加入数分钟的密集战斗、手机、不同分辨率和高刷新率测试。固定池避免无限增长，并不代表任意数量的透明物体都没有绘制成本。
5. **继续沿用原画分层的敌人方向。** 在用户允许时，把手、尾、发梢、武器单独分层，增加攻击预备、受击和转身动作。正式替换角色模型前先确认形象；不要为了立体化重新设计脸和服装。
6. **地图继续围绕辨路与战斗视线细化。** A/B 区域可分别增加蓝绿布料与赭红旗帜；装饰重点放在墙边、入口和高处。先验证出生点、门洞、Boss 活动空间，再增加实体障碍。
7. **加分档画质并实测设备。** 优先提供像素比、阴影分辨率、植被数量和动态水面开关。在实际集显和手机上测量，再选择是否增加后处理；当前不建议直接堆重型 SSAO、实时反射或大量动态点光源。
8. **统一武器骨架与动作事件。** 后续模型应提供 `grip`、`muzzleTip`、`eject` 等锚点，并遵守坐标轴约定；新武器接入先跑瞄准回归。将近战的伤害事件与挥刀动作时间线进一步统一，补蓄力提示和恢复动作，再考虑独立第一人称武器渲染层，改善贴墙穿插。
9. **用战斗时钟统一暂停。** 当前新战斗特效已冻结，但旧的敌人待机、部分剑气等仍依赖视觉时钟。后续显式区分战斗时间与菜单演出时间，避免每个模块各写一套暂停规则。

## 8. 追加修复：站到墙顶后出现重叠闪烁

用户反馈跳上围墙后，顶部出现重叠面闪烁。检查确认这是第一轮新增檐口与原墙顶共面引起的 **z-fighting**：直墙采样处有 2 层表面，中央和 A/B 围场转角有 4 层表面争用同一深度。

- `js/art.js` 删除被檐口覆盖的原墙体朝上三角形，保留墙体侧面。
- 同高度檐口按矩形并集生成一个完整网格；相交区域只生成一次顶面，侧面只沿外轮廓生成，消除转角的重复面。
- 墙顶仍位于原高度，没有抬升檐口，也没有使用深度偏移遮掩重复几何。原碰撞体与玩家落脚高度保持不变。

### 10.2 新规则与操作

- **队伍规模**：6v6、8v8、12v12、16v16，默认 8v8；红队含玩家，蓝队全为 AI。仍是本地单机对抗。
- **额度**：每队共享一份；默认人数 × 3，可选 × 2 或 × 5。初始部署不扣，阵亡扣 1。最后一点被扣完立即判负，该次不再复活；存活队员无需再被全部击倒。
- **复活**：阵亡后 4 秒回己方基地，生命及枪械弹药补满、1 枚手雷，出生保护 1.5 秒。开火、刀击、投雷解除保护。玩家死亡期间可看到队友视角。
- **回合**：准备 3 秒，回合结束停留 3 秒后重新部署，双方额度重置；先赢 4 回合、最多 7 回合。界面计时显示已用时，不额外加超时判胜规则。
- **累计战绩**：K/D 跨回合保留；Tab 查看阵亡读秒和双队计分板。
- **操作**：1 步枪、2 所选副武器、3 匕首；左键射击/轻击、右键匕首重击、R 换弹、G 手雷、Ctrl/C 蹲下。

执行者：**OpenAI Codex，基于 GPT-6 的 AI 编程助手**。本次直接修改现有 Three.js 项目，在上一轮 FPS 改造的基础上补齐操作与反馈。原始敌人素材、AI 规则及地图几何保持上一轮版本；新增图标通过本地 SVG 绘制，无外部下载或新增运行依赖。

### 11.1 网页全屏与输入

- 无尽模式和歼灭战在点击进入的同一用户手势内调用 Fullscreen API，然后继续已有的分阶段载入。这样不会因为等待地图构建而失去浏览器要求的用户激活。
- 点击继续游戏会再次请求全屏。浏览器不支持或拒绝时保留窗口模式，并提供 **F / 右上角全屏入口**；拒绝不会中止载入，也不会产生未处理的 Promise 异常。
- 在支持且授权的浏览器中调用 Keyboard Lock 捕获 WASD、R/G/I/F、切枪键、方向键、空格和 Tab。游戏处理这些键时阻止默认行为，减少蹲下时 Ctrl+W、Ctrl+R 等组合误触浏览器。
- 不额外锁定 Esc、Alt、Meta 和功能键；系统保留组合键以平台行为为准。失去窗口焦点、退出全屏会暂停并清空持续移动/开火、触屏摇杆及计分板状态。菜单/暂停释放键盘锁，菜单 Tab 可以正常导航。
- 地图载入时退出全屏，载入完成后停留在暂停页；迟到的指针锁定结果不能擅自把暂停页或菜单恢复成战斗。

兼容边界：全屏和键盘捕获受浏览器支持、权限和操作系统限制，不能保证拦截全部系统快捷键。Edge 验收分别覆盖了授权成功及拒绝路径；其它浏览器需按实际设备补测。实现依据：[MDN Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)、[Chrome Keyboard Lock 文档](https://developer.chrome.com/docs/capabilities/web-apis/keyboard-lock)。

### 13.1 顶棚下跳跃“闪现”的原因与修复

原 `updatePlayer` 仅在下降时检测障碍顶面，没有对上升中的头部做检测；头部进入顶棚后，旧水平碰撞分支会把玩家位置直接设到整个障碍 AABB 的另一侧边缘，产生大幅位移。

新增 `js/player-physics.js`，由无尽与 FPS 共用：

- 上升扫掠检测头部跨越顶棚底面，停在接触高度并清零上升速度；下降扫掠落在实际跨越的最高支撑面。
- 水平轴扫掠仅限制本次请求位移，保留沿墙滑动；取消把重叠角色强制投到远处边缘的逻辑。内部短步进配合扫掠，避免薄墙/薄顶棚穿越。
- 身体头顶在视高上增加 0.16 米余量，相机反馈最大上移 0.08 米。蹲姿平滑恢复前检查空间，低顶棚下保持必要蹲姿，离开后恢复站立。
- 修正浮点时间在恰好 60Hz 时偶尔多切一步的问题，保证同一跳跃在连续帧中的时序稳定。仍能跳上原来的 0.95/1.65 米木箱及石头。

实机验证：新地图 B 通道和原图 B 洞顶棚底面都是 3.4 米。站姿跳起脚底最高 **1.54 米**，原地跳跃水平位移为 0；移动中没有超过输入速度的瞬移。正常落地、箱顶支撑、离开边缘、蹲姿恢复和高速薄顶棚另有独立测试。

### 14.4 手雷：移动跳投、反弹与定时引信

移除了旧的固定 13m/s 抛射和触地即炸逻辑。新增 `js/grenade-physics.js`，独立于 Three.js，可测试纯物理。

- **按下 G / 触屏手雷按钮**：扣除一颗手雷，启动 3 秒引信、收枪并举雷。**松开**：投出；快速按放是普通快投，按住后再松开可以提前预热、预判或空爆。按用户后续反馈，已移除屏幕中央的引信倒计时浮窗，保留举雷动作、手雷数量与操作指南。一直不松手会在手中爆炸并自伤。
- 初速度为瞄准方向 × 15.5，加 3.3m/s 上抛分量；叠加玩家真实碰撞解算后的全部水平速度及 85% 垂直速度。重力为 −15m/s²。前冲更远、后退更近、侧移偏移，起跳和下落都会改变轨迹；顶墙按 W 不会虚增速度。
- 弹体半径 0.14 米，最多 1/120 秒子步，连续扫掠地面和障碍物；出手点也从玩家眼部向前扫掠，避免贴墙时生成在墙后。
- 地面回弹 0.38、墙面回弹 0.52，加入切向摩擦、低速休眠、翻滚与落地声音。落地/撞墙不引爆，低速静止后仍走引信；积分精确截在引信到期时刻，空中同样爆炸。
- 持雷与 0.42 秒收手动作中，枪、刀、换弹和切枪互斥。暂停冻结持雷和已投掷弹体；暂停中松开会在恢复后投出；阵亡掉落已启动的手雷；回合切换和退出清理持雷模型及动作状态。
- 两个模式共用新投掷物理，伤害数值仍按原模式处理。FPS 保留敌我识别、墙体遮挡及自伤；无尽保留技能与天气加成。引信、重力、回弹等常量集中在物理模块，避免旧 `CFG.nadeDrop` 成为失效配置。
