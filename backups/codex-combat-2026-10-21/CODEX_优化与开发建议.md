# Codex 优化记录与后续开发建议

日期：2026-10-21（北京时间）  
执行者：**OpenAI Codex，基于 GPT-6 的 AI 编程助手**。本轮在用户授权下直接检查并修改此项目。原有游戏由 DeepSeek 开发，本文件记录 Codex 接手的这一轮工作，供项目所有者及后续开发者交接使用。

这是一轮基于 V0.5.2 的美术与维护补丁，继续使用本地 Three.js r159、普通 script 标签和原有启动方式。

## 1. 敌人：保留原画，改善空间表现

- **没有替换或重绘** `assets/蓝色大肥鱼.png` 和 `assets/fish-texture.js`。脸、头发、衣服、整体轮廓继续来自原素材。
- 普通敌人与 Boss 的单面板改为 **12×12 分段的浅弧面**，增加一个紧贴原画的深色背层，形成很薄的立体边缘。这属于 2.5D 浅浮雕，并非完整的角色三维建模。
- 增加轻微呼吸伸缩、较小幅度的左右摆动和接地软阴影；跳起时软阴影扩大、变淡。分裂子鱼显示为原体型的 72%。
- 广告牌只跟随水平视角，玩家抬头、低头时，角色不会整张向地面翻倒。Boss 同样处理。
- 修正原有抠图：旧逻辑会全图删除接近白色的像素，导致白衣、眼白、头饰出现透明洞。现在只删除与图片边缘连通的背景区域，原图内部的白色被保留。
- 将 `customDepthMaterial` 正确挂在 Mesh 上，投影使用角色透明轮廓。角色原画保持不受色调映射影响，以保证辨识度。

## 2. 地图：沙海哨站

保留中央建筑、A/B 区域、两侧走廊、绿洲和主要掩体位置，在原有沙漠城上细化：

| 部位 | 本轮变化 |
| --- | --- |
| 墙面 | 512px 砂岩纹理、表面凹凸、细颗粒；UV 按米数展开，长墙不再把少数砖块横向拉长 |
| 建筑 | 檐口、墙基、竖向装饰、四向拱门、青绿百叶窗、窗台、灯具、A/B 导视 |
| 地面 | 风纹沙地、石板道路、庭院拼花、道路边饰 |
| 植被 | 用弯曲树干和分段棕榈叶替换球形树冠，增加轻微风摆；低矮草叶替换锥形草丛 |
| 绿洲 | 青绿色水面、移动水纹与凹凸、分块石砌池边 |
| 掩体 | 固定箱子和随机掩体采用木板、金属包边与斜撑纹理；保留原有碰撞体 |
| 远景 | 城墙外的塔楼、分层砂岩台地、日月与夜空星点 |
| 光照 | 明确 sRGB 输出、ACES 色调映射；调整日间配色；五种环境同步切换天空、雾、灯光和环境反射 |

五种环境原有的玩法修饰仍保留。修正了“天空已变深夜，墙面却仍受白天环境反射照亮”的问题。

场景装饰主要是视觉层；新增拱门、遮阳布、城外远景不作为新的可攀爬掩体。若后续要让这些装饰承担战斗遮挡或站立功能，应同时补充对应的碰撞和射线遮挡配置。

## 3. 代码与性能维护

- 新增 `js/art.js`，集中管理材质、程序化纹理、场景细节、角色浅弧面和资源释放。删去 `game.js` 中已不再使用的旧美术生成函数。
- 固定数量的通用纹理、材质与基础几何体缓存复用；建筑装饰、草叶和台地采用 `InstancedMesh` 批量绘制。
- 美术使用独立的固定种子随机数，绘制细节不会额外消耗战斗逻辑的 `Math.random()` 序列。
- 新波次开始时移除旧波次的死亡敌人，停止对应语音，并回收模型和阴影的临时资源。原实现会持续保留死亡对象。
- 回主菜单时递归回收环境几何、临时材质、贴图、实例缓冲和灯光阴影资源；修复随机掩体重开后未被完整卸载的问题。
- 补给拾取、手雷爆炸和重开清场时，释放相应临时模型资源。
- HUD 数值未变化时跳过重复 DOM 写入；小地图绘制限制为 30 次/秒，移动、射击与 3D 渲染仍按原帧循环运行。
- 修复暂停、技能或奖励界面中换弹计时仍推进的问题。恢复游戏后继续原有换弹进度。
- 随机掩体重新生成时重建小地图，避免地图显示上一局的箱子。
- 调试接口 `FishGame.__debug.getSceneStats()` 增加被跟踪敌人数、绘制调用数、三角形数、几何和贴图计数，便于以后排查。

资源释放约定：`userData.artShared` 标记长期共享的美术缓存；释放敌人时显式保护 `fishTex`。新增共享资源时请沿用这个约定，避免提前释放其他对象仍在使用的贴图或材质。

- `node tests/smoke-test.js`：**158 项通过**。新增原画白色保护、暂停换弹、死亡敌人资源回收、退出清场与重新进入等回归检查。射击测试先清除随机掩体，避免测试目标偶然被随机箱子挡住。
- `node tests/e2e-test.js`：**6 项通过**，包含新美术脚本加载、并发请求、内容一致性、404 和目录穿越检查。
- `tests/browser-art-test.cjs`：在 **Edge 无头浏览器的真实 WebGL 上通过**，包含实际射线命中、移动、三武器切换、暂停换弹、五种环境、原画浅弧模型和 `file://` 离线启动。
- 四轮“建图、渲染、换波、回菜单”检查通过：旧敌人数不随波次累积；退出后的几何与贴图计数在暖机后保持稳定。

这些验证覆盖本机自动化测试与截图检查；没有进行完整百波人工试玩，也没有将无头浏览器结果作为手机性能或帧率提升保证。

## 5. 启动、测试与回退

直接双击 `index.html`，或双击 `启动游戏.bat`，也可在此目录执行：

```powershell
node server.js
# 浏览器打开 http://127.0.0.1:8123/
```

浏览器测试需开发环境提供 Playwright。Windows 默认调用本机 Edge；其他系统需准备 Playwright Chromium。先启动服务器，再运行：

```powershell
node tests/browser-art-test.cjs
# 已有外部 Playwright 时，可将 PLAYWRIGHT_MODULE 环境变量设为其模块目录。
# 可选 FISH_TEST_URL 指定服务器地址，FISH_TEST_OUTPUT 指定输出目录。
```

**游戏运行本身无需安装新依赖，也没有新增 CDN、远程贴图或付费资源。** 脚本顺序为 `three.min.js → fish-texture.js → art.js → game.js`。

原文件备份位于 `backups/codex-2026-10-21/`，保留本轮改动前的 `index.html`、`js/game.js`、`README.md` 和两个已有测试文件。回退时关闭游戏，把备份中的文件按原路径复制回项目即可；本轮新增的美术模块与测试文件可以保留，旧入口不会引用它们。备份不包含个人存档，浏览器存档结构本轮未改动。

## 6. 给后续开发者的建议

1. **先拆职责，再加玩法。** `game.js` 仍然较大。按“状态与时间、敌人 AI、武器、波次与成长、UI、音频”逐块抽离，保留现有行为测试。先继续用 classic script 也可以；是否迁移 ESM/Vite，应同时考虑双击离线启动的要求。
2. **统一碰撞与可见模型。** 目前主要依赖矩形障碍和角色网格射线，棕榈等物体仍沿用原有近似碰撞。建议给地图对象提供统一的 collider/occluder 配置，并决定敌人采用稳定的逻辑命中体还是按原画 alpha 判定，避免以后美术变形无意改变射击手感。
3. **补敌人绕路能力。** 当前主要是直接追击和局部避障。沙漠走廊更适合简化网格 A* 或导航点图；索敌视线检查和寻路分帧执行，减少大量敌人同时更新的开销。
4. **为长局建立压力场景。** 自动刷入各类敌人、Boss、投射物和反复爆炸，记录数分钟的帧耗时与 `renderer.info.memory`。此次验证了场景与敌人的主要生命周期，后续应把所有攻击特效和武器缓存纳入统一的资源管理约定。
5. **继续沿用原画分层的敌人方向。** 在用户允许时，把手、尾、发梢、武器单独分层，增加攻击预备、受击和转身动作。正式替换角色模型前先确认形象；不要为了立体化重新设计脸和服装。
6. **地图继续围绕辨路与战斗视线细化。** A/B 区域可分别增加蓝绿布料与赭红旗帜；装饰重点放在墙边、入口和高处。先验证出生点、门洞、Boss 活动空间，再增加实体障碍。
7. **加分档画质并实测设备。** 优先提供像素比、阴影分辨率、植被数量和动态水面开关。在实际集显和手机上测量，再选择是否增加后处理；当前不建议直接堆重型 SSAO、实时反射或大量动态点光源。
